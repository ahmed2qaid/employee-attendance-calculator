# Employee Attendance Calculator

مستودع واحد يحتوي أربع معماريات مختلفة لنفس نظام حساب دوام الموظفين.

## الفروع
- `nextjs-standalone`: Next.js بدون Backend، حفظ محلي، PDF، مناسب Netlify/Vercel. هذه النسخة وحدها تسمح بتخصيص وقت بداية ونهاية كل وردية لكل موظف.
- `nextjs-supabase`: Next.js + Supabase.
- `flutter-web-supabase`: Flutter Web + Supabase.
- `laravel-supabase`: Laravel + Supabase PostgreSQL.

## سياسة الدوام الموحدة
- يوم العمل = 8 ساعات = 480 دقيقة.
- الجمعة مستثناة تلقائيًا.
- سماح التأخير قاعدة عامة واحدة لجميع الموظفين.
- سماح الانصراف المبكر قاعدة عامة واحدة لجميع الموظفين.
- لا يوجد تخصيص للسماح لكل موظف.
- إذا تجاوز الموظف حد السماح تُحتسب مدة التأخير أو الانصراف المبكر كاملة.
- لا توجد بصمتا دخول وخروج = غياب.
- بصمة واحدة فقط = يوم معلق.
- الحساب بالدقائق دون تقريب.

## الوقت الإضافي
- الوقت الإضافي يبدأ من الدقيقة الأولى بعد نهاية الوردية المجدولة لذلك اليوم.
- مثال: إذا كانت الوردية 06:00–14:00 وسجل الموظف خروجًا 15:20، فالوقت الإضافي = ساعة و20 دقيقة.
- إذا خرج الموظف عند نهاية الدوام أو قبلها، فالوقت الإضافي = صفر.
- في نظام الورديتين المتناوبتين، يحدد النظام أولًا الوردية الصحيحة لذلك التاريخ ثم يحسب الوقت الإضافي بعد نهاية تلك الوردية.
- يظهر الوقت الإضافي لكل يوم ويُجمع إجماليًا لكل موظف.

## نظام الورديات
كل موظف يمكن أن يعمل بأحد النظامين:
1. **وردية واحدة ثابتة**.
2. **ورديتان متناوبتان أسبوعيًا**: وردية 1 لمدة 7 أيام، ثم وردية 2 لمدة 7 أيام، ثم العودة إلى الأولى، وهكذا.

عند اختيار الورديتين يُحدد تاريخ بداية الدورة، والنظام يحسب الوردية الصحيحة لكل يوم انطلاقًا من هذا التاريخ، حتى عند الانتقال بين شهرين أو سنتين مختلفتين.

الورديات القياسية في الفروع المتصلة بقاعدة البيانات:
- صباحي: 06:00–14:00.
- مسائي: 14:00–22:00.

وفي `nextjs-standalone` فقط يمكن تخصيص أوقات الوردية 1 والوردية 2 لكل موظف.

اختر الفرع المناسب واقرأ `README.md` و`SETUP.md` داخله.
