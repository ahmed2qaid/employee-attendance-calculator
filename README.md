# Employee Attendance Calculator — Next.js Standalone

نسخة Next.js مستقلة بالكامل بدون Supabase وبدون Backend.

## الوظائف
- إدارة عدة موظفين داخل نفس المتصفح.
- وردية مستقلة لكل موظف: 06:00–14:00 أو 14:00–22:00 أو مرنة.
- شهر كامل، دورة 26–25، أو فترة مخصصة.
- اكتشاف الجمعة واستثناؤها تلقائيًا.
- إدخال الحضور والانصراف يومًا بيوم.
- تعبئة أوقات الوردية القياسية ثم تعديل الأيام الاستثنائية.
- حساب الساعات والدقائق وأيام العمل المكافئة لحظيًا وبدون تقريب.
- 8 ساعات = 480 دقيقة = يوم عمل واحد.
- حفظ البيانات في Local Storage.
- تقرير فردي وتقرير إجمالي لجميع الموظفين.
- تصدير PDF عن طريق نافذة الطباعة / Save as PDF.
- جاهز لـ Netlify وVercel كـ Static Export.

## إعدادات التهيئة المرنة
المشروع لم يعد يعتمد على قيم ثابتة داخل الكود لسماح التأخير أو الانصراف المبكر.

يوجد مستويان للإعداد:
1. **إعدادات افتراضية عامة**: يحدد المستخدم سماح التأخير وسماح الانصراف المبكر بالدقائق. كل موظف جديد يرث هذه القيم تلقائيًا.
2. **إعدادات خاصة لكل موظف**: يمكن تعديل السماحين لأي موظف بشكل مستقل دون التأثير على بقية الموظفين.

مثال:
- الافتراضي العام: تأخير 15 دقيقة، انصراف مبكر 5 دقائق.
- الموظف أحمد: تأخير 10 دقائق، انصراف مبكر 0 دقيقة.
- الموظف محمد: تأخير 20 دقيقة، انصراف مبكر 10 دقائق.

يمكن إدخال 0 أو أي عدد دقائق مناسب لسياسة الشركة. يوجد أيضًا زر لتطبيق القيم الافتراضية الحالية على جميع الموظفين الموجودين.

## طريقة الحساب
- يوم الجمعة إجازة ولا يدخل في الحساب.
- إذا كان التأخير أقل من أو يساوي سماح الموظف فلا يسجل تأخير.
- إذا تجاوز التأخير السماح، تحسب مدة التأخير كاملة من بداية الوردية، بما فيها دقائق السماح.
- إذا كان الانصراف المبكر أقل من أو يساوي سماح الموظف فلا يسجل انصراف مبكر.
- إذا تجاوز السماح، تحسب مدة الانصراف المبكر كاملة حتى نهاية الوردية.
- لا توجد بصمة دخول ولا خروج في يوم عمل = غياب.
- توجد بصمة واحدة فقط = يوم معلق.
- وجود بصمتي الدخول والخروج = حضور، وتحسب ساعات الحضور الفعلية.
- الوردية المرنة تحسب ساعات الحضور فقط ولا تحسب تأخيرًا أو انصرافًا مبكرًا لعدم وجود وقت قياسي للمقارنة.
